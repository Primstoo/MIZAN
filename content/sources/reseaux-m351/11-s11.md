```html
<p><b>Rôle :</b> assurer une transmission fiable entre deux machines directement connectées. Elle encapsule le paquet dans une <b>trame</b> : en-tête (adressage MAC) + paquet + queue (FCS/CRC). <b>Services :</b> délimitation des trames, contrôle d'erreurs, contrôle de flux, contrôle d'accès au support (MAC). Technologies : Ethernet, Wi-Fi, PPP, switchs.</p>
  <p><b>Sous-couches :</b> <b>LLC</b> (en haut : vers la couche réseau, indique le protocole de couche 3) et <b>MAC</b> (en bas : vers la couche physique, adressage, début et fin de trame). <b>Accès au support partagé :</b> contrôlé (chacun son tour, déterministe) ou basé sur le conflit (aléatoire : CSMA/CD, CSMA/CA).</p>
  <p><b>Contrôle de flux :</b> <i>Send and Wait</i> (une trame, un sens, acquittement) ou <i>fenêtre d'anticipation</i> (plusieurs trames, deux sens, numéros de séquence).</p>
  <h3>Délimitation des trames</h3>
  <div class="formula">Fanion = 01111110   (HDLC, PPP)
Bit de transparence : insérer un 0 après chaque suite de cinq 1 (le récepteur le retire)
Ex. 0111111011111100  →  011111[0]1011111[0]100</div>
  <h3>Parité (VRC, LRC)</h3>
  <div class="formula">Parité paire   : nombre total de 1 (bit de parité compris) PAIR
Parité impaire : nombre total de 1 IMPAIR
Exemple du cours : 0011010 (trois 1)  → paire 0011010<b>1</b>   impaire 0011010<b>0</b></div>
  <p><b>VRC</b> (parité par caractère) : simple, mais ne détecte que les erreurs portant sur un nombre <b>impair</b> de bits. <b>LRC</b> (parité sur tout le bloc, position par position) : combinée à la VRC, elle <b>localise et corrige</b> une erreur simple, à l'intersection de la ligne et de la colonne fautives.</p>
  <div class="trap"><b>Écart dans le cours</b>La diapo 96 parle de « LRC » pour la parité par caractère, alors que les diapos 98-99 appellent cela VRC et réservent LRC au bloc. Utilise la version des diapos 98-99 : VRC = par caractère, LRC = par bloc.</div>
  <h3>CRC</h3>
  <div class="formula">Émission : r = degré de G(x)
  1. M(x) suivi de r zéros
  2. Division modulo 2 (XOR, sans retenue) par G(x) → reste R(x) sur r bits
  3. Trame émise T = M suivi de R
Réception : T'(x) / G(x) → reste 0 : pas d'erreur ; reste ≠ 0 : erreur → retransmission

Exemple vérifié : M = 1101011011, G = 10011 (x⁴ + x + 1)
  → R = 1110, T = 11010110111110</div>
  <div class="trap"><b>Pièges</b>① On ajoute autant de zéros que le DEGRÉ de G (le nombre de bits de G moins 1), pas le nombre de bits de G. ② En modulo 2, soustraction = addition = XOR. ③ Le reste fait toujours r bits : garde les zéros de tête (ex. 0110).</div>
  <p class="small muted">Les diapos 101 à 104 (algorithme CRC détaillé) sont des images que je n'ai pas pu lire. J'ai appliqué la méthode standard, qui est cohérente avec la diapo 105. Si ton prof note le calcul autrement, envoie-moi une photo.</p>
  <h3>Code de Hamming</h3>
  <div class="formula">C(n,k) : n = 2^r − 1, r = n − k      (7,4) : r = 3 ; (15,11) : r = 4
Disposition (cours) :  pos 1  2  3  4  5  6  7
                           C0 C1 U0 C2 U1 U2 U3
C0 = U0 + U1 + U3      C1 = U0 + U2 + U3      C2 = U1 + U2 + U3     (mod 2)

Exemple du cours : m = 1010 → C0 = 1, C1 = 0, C2 = 1 → émis 1011010
Réception 1011000 : C'0 ok ; C'1 faux (+2) ; C'2 faux (+4) → bit n° 6 erroné</div>
  <div class="exam"><b>Ce qui tombe</b>Calculer un bit de parité, un CRC, un mot de Hamming, puis localiser une erreur de Hamming. Entraîne-toi dans l'onglet Calculs : les exercices sont générés et vérifiés automatiquement.</div>
  <h3>La trame Ethernet (TD 2, ex. 2)</h3>
  <div class="table-wrap"><table><thead><tr><th>Champ</th><th>Taille</th><th>Rôle</th></tr></thead><tbody><tr><td>Préambule</td><td>7 octets</td><td>aa aa aa aa aa aa aa (10101010) : synchronisation de l'horloge du récepteur</td></tr><tr><td>SFD</td><td>1 octet</td><td>ab (10101011) : annonce le début de la trame</td></tr><tr><td>MAC destination</td><td>6 octets</td><td>adresse physique du destinataire</td></tr><tr><td>MAC source</td><td>6 octets</td><td>adresse physique de l'émetteur</td></tr><tr><td>EtherType</td><td>2 octets</td><td>protocole encapsulé : 0800 = IPv4, 0806 = ARP, 86DD = IPv6</td></tr><tr><td>Données</td><td>46 à 1500 octets</td><td>le paquet ; complété par du bourrage (padding) s'il fait moins de 46 octets</td></tr><tr><td>FCS</td><td>4 octets</td><td>séquence de contrôle (CRC-32) : le récepteur la recalcule et rejette la trame si elle diffère</td></tr></tbody></table></div>
  <p>Hors préambule et SFD, une trame fait <b>64 à 1518 octets</b> (14 d'en-tête + 46 à 1500 de données + 4 de FCS). Une adresse MAC s'écrit en 6 octets hexadécimaux : les 3 premiers sont l'OUI du fabricant.</p>
  <div class="def"><b>Méthode de décodage</b>Découpe la suite d'octets dans l'ordre : 8 octets de début (préambule + SFD), 6 (destination), 6 (source), 2 (EtherType), puis les données, et les 4 derniers octets (FCS). Si l'EtherType vaut 0800, les données commencent par un en-tête IPv4 (octet 45 = version 4, longueur d'en-tête 5 × 4 = 20 octets) ; le champ Protocole de cet en-tête (06 = TCP, 11 = UDP, 01 = ICMP) dit ce qui suit.</div>
```

{n29@83} Limite de la parité simple (VRC) ? :: Elle ne détecte que les erreurs portant sur un nombre IMPAIR de bits. Deux bits faux s'annulent et passent inaperçus.
{n29@84} VRC + LRC (parité croisée) ? :: VRC : un bit de parité par caractère (mot).<br>LRC : un bit de parité par position, sur tout le bloc.<br>Ensemble, ils détectent ET localisent une erreur simple, qu'on peut donc corriger.
{n30@85} Principe du codage CRC (émission) ? :: Ajouter r zéros à M (r = degré de G), diviser modulo 2 (XOR) par G, garder le reste R sur r bits. Trame émise T = M suivi de R.
{n30@86} Vérification CRC (réception) ? :: On divise la suite reçue T'(x) par G(x).<br>Reste R'(x) = 0 → pas d'erreur.<br>Reste ≠ 0 → erreur, on demande la retransmission.
{n30@87} Autres noms de la zone de contrôle ? :: CRC (Cyclic Redundancy Check) ou FCS (Frame Check Sequence).
{n31@88} Hamming C(n,k) : relations ? :: n = 2^r − 1 et r = n − k.<br>Ex. : n = 7, r = 3, k = 4 ; n = 15, r = 4, k = 11.
{n31@89} Hamming (7,4) : disposition des bits (cours) ? :: Positions 1 à 7 : C0 C1 U0 C2 U1 U2 U3.<br>Les contrôles sont aux puissances de 2 : 1, 2, 4.
{n31@90} Formules des bits de contrôle (cours) ? :: C0 = U0 + U1 + U3<br>C1 = U0 + U2 + U3<br>C2 = U1 + U2 + U3<br>(somme modulo 2)

{n31@92} Hamming : localiser l'erreur ? :: Recalculer chaque Ci. S'il est différent du Ci reçu, ajouter sa position (1, 2 ou 4) au compteur C. C = 0 : pas d'erreur ; sinon C = numéro du bit erroné.<br>Ex. : 1011000 reçu → C = 2 + 4 = 6.

{n41@134} EtherType 0800, 0806, 86DD ? :: 0800 = IPv4 · 0806 = ARP · 86DD = IPv6.
{n41@135} Que contiennent les 4 derniers octets d'une trame Ethernet ? :: Le FCS (séquence de contrôle, CRC-32) : le récepteur le recalcule ; s'il diffère, la trame est rejetée.
{n41@136} Taille minimale et maximale d'une trame Ethernet (hors préambule) ? :: 64 à 1518 octets : données de 46 à 1500 octets, avec du bourrage (padding) si elles sont plus courtes que 46.

- MAC
+ LLC
- PHY
- IP

- Accès aléatoire
+ Accès contrôlé (déterministe)
- CSMA/CD
- Accès par conflit

? {n37} Dans le protocole « Send and Wait »…
- Plusieurs trames partent à la fois
+ Une seule trame est envoyée, puis on attend l'acquittement
- Les données circulent dans les deux sens
- Il n'y a pas d'acquittement
= Send and Wait : une trame à la fois, dans un sens, avec acquittement. La fenêtre d'anticipation envoie plusieurs trames.

? {n29} Bit de parité PAIRE pour 1101001 ?
+ 0
- 1
= 1101001 contient quatre 1 (nombre pair), donc le bit de parité paire vaut 0.

? {n29} La parité simple (VRC) ne détecte pas…
- Une erreur sur 1 bit
- Une erreur sur 3 bits
+ Une erreur sur 2 bits
- Aucune erreur

- Seulement de détecter
+ De détecter et de corriger une erreur simple
- De corriger toutes les erreurs
- De compresser
= L'intersection de la ligne et de la colonne fautives localise le bit, qu'on peut donc corriger.

- 3
+ 4
- 5
- 8

- Erreur détectée
+ Pas d'erreur détectée
- Il faut corriger le bit 0
- G est faux
= R'(x) = 0 : le mot reçu est un mot de code valide.

+ 1110
- 0111
- 1011
- 0000
= Vérifié par calcul : on ajoute 0000, puis on divise modulo 2 par 10011 → R = 1110, donc T = 11010110111110.

? {n31} Pour un code de Hamming avec r = 4, n vaut…
- 7
+ 15
- 16
- 11

? {n31} Code de Hamming (convention du cours) de 1010 ?
+ 1011010
- 1010101
- 0110010
- 1011001
= C0 = 1+0+0 = 1, C1 = 1+1+0 = 0, C2 = 0+1+0 = 1. Ordre C0 C1 U0 C2 U1 U2 U3 → 1011010.
