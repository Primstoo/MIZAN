  <p><b>Ports réservés :</b> 0 à 1023. Le numéro de port permet d'identifier la conversation, c'est-à-dire l'application à qui sont destinées les données.</p>
  <p><b>WWW</b> : ensemble des pages reliées par hyperliens. <b>HTML</b> : langage de description des pages. <b>HTTP</b> : protocole qui les transporte. <b>URL</b> : adresse d'une ressource Web ; <code>http://www.fpbm.ma/web-server.htm</code> = protocole + nom du serveur + fichier demandé.</p>
  <p><b>Messagerie :</b> le MUA est le client (Outlook) ; le MTA transfère entre serveurs ; le MDA dépose le message dans la boîte. Syntaxe d'une adresse e-mail : <code>utilisateur@domaine</code> (ex. nom@fpbm.ma).</p>
  <div class="table-wrap"><table><thead><tr><th>TCP</th><th>UDP</th></tr></thead><tbody>
  <tr><td>Fiable, orienté connexion (SYN, SYN-ACK, ACK)</td><td>Non fiable, sans connexion</td></tr>
  <tr><td>Contrôle d'erreurs, de flux, de congestion ; remise dans l'ordre ; accusés de réception</td><td>Aucun de ces contrôles, mais rapide et léger</td></tr>
  <tr><td>En-tête de 20 octets · HTTP, SMTP, FTP, Telnet</td><td>DNS (couramment), SNMP, VoIP, DHCP</td></tr></tbody></table></div>
  <h3>MTU, MSS et segmentation</h3>
  <div class="formula">MTU (Maximum Transmission Unit) = taille max d'un paquet sur l'interface (Ethernet : 1500 o)
MSS (Maximum Segment Size)       = MTU − 40   (20 o en-tête IP + 20 o en-tête TCP) → 1460 o

Nb de segments = ⌈ données / (MTU − en-têtes) ⌉
Dernier segment = données restantes + en-têtes</div>
  <div class="trap"><b>Piège (TD ex. 5)</b>Repère bien ce que l'énoncé compte comme « en-têtes » : 20 octets au total, ou 20 par en-tête (IP + TCP = 40, comme dans le cours pour le MSS). Écris ton hypothèse sur ta copie.</div>
  <p><b>Équipements :</b> la <b>carte réseau</b> relie l'hôte au support et porte l'adresse MAC ; le <b>répéteur</b> régénère le signal (couche 1) ; le <b>switch</b> relie les hôtes d'un même réseau (couche 2) ; le <b>routeur</b> relie des réseaux différents (couche 3). L'<b>adresse IP</b> est logique et modifiable ; l'adresse <b>MAC</b> est physique et en principe fixe.</p>
  <h3>Transport, compléments</h3>
  <p>Fonctions : segmentation et réassemblage, contrôle de flux, contrôle d'erreurs, multiplexage et démultiplexage, fiabilité, identification des conversations (ports). La <b>taille de fenêtre</b> est le nombre d'octets envoyés avant d'attendre un accusé de réception ; le <b>numéro d'ACK</b> est le numéro du prochain octet attendu. En cas d'encombrement, le destinataire acquitte le dernier segment reçu dans l'ordre et réduit la fenêtre. La <b>fermeture</b> se fait en 4 temps : FIN → ACK → FIN → ACK.</p>
  <p><b>HTTP :</b> requêtes GET (obtenir), POST (envoyer des données dans le message), PUT (téléverser une ressource). Codes : 200 OK · 301 déplacé définitivement · 400 syntaxe erronée · 404 non trouvé · 505 version non gérée. Un serveur Web stocke les objets adressés par URL (Apache, IIS).</p>
  <h3>Messagerie : le chemin d'un e-mail (TD 2, ex. 1)</h3>
  <div class="formula">zzz@yahoo.fr ──(SMTP)──▶ MTA yahoo.fr ──(SMTP)──▶ MTA gmail.com ──(MDA)──▶ boîte de yyy@gmail.com
  MUA                      │  DNS : enregistrement MX de gmail.com                     │
                                                                          MUA ◀──(POP3 ou IMAP)──┘</div>
  <ul>
    <li><b>MUA</b> (client : Outlook, Thunderbird, webmail) envoie par <b>SMTP</b> à son serveur. Le <b>MTA</b> de l'expéditeur interroge le <b>DNS</b> (enregistrement MX du domaine du destinataire) puis transfère par SMTP au MTA du destinataire. Le <b>MDA</b> dépose le message dans la boîte. Le destinataire le lit avec son MUA par <b>POP3</b> ou <b>IMAP</b> (ou en webmail, par HTTP).</li>
    <li>SMTP <b>pousse</b> le courrier (client → serveur et serveur → serveur) ; POP3 et IMAP le <b>récupèrent</b> (serveur → client).</li>
  </ul>
  <div class="table-wrap"><table><thead><tr><th>Critère</th><th>POP3 (TCP 110)</th><th>IMAP (TCP 143)</th></tr></thead><tbody><tr><td>Flux</td><td>le client télécharge les messages vers sa machine, souvent en les supprimant du serveur</td><td>le client consulte les messages sur le serveur ; seules les actions (lecture, suppression) se synchronisent</td></tr><tr><td>Stockage côté serveur</td><td>minimal</td><td>tout reste sur le serveur</td></tr><tr><td>Dossiers</td><td>une seule boîte de réception</td><td>plusieurs dossiers (brouillons, envoyés, archives, spam)</td></tr><tr><td>Accès multiple</td><td>un seul appareil, pas de synchronisation</td><td>plusieurs appareils synchronisés</td></tr></tbody></table></div>
  <p>En une phrase : POP3 pour un usage simple sur un seul poste ; IMAP pour un usage connecté et multi-appareils. Ports standards : 110 (POP3), 143 (IMAP), 25 (SMTP).</p>
  <h3>TCP : numéros de séquence, acquittements et fenêtres (TD 2, ex. 3 à 5)</h3>
  <div class="formula">Seq     = numéro du premier octet de données du segment
Prochain Seq = Seq + longueur utile (payload)
ACK     = numéro du prochain octet attendu = dernier octet reçu EN ORDRE + 1
Exemple : Seq initial 2001, segments de 1000, 1000, 500 octets
  segment 1 : Seq 2001  (octets 2001 à 3000)  → ACK attendu 3001
  segment 2 : Seq 3001  (octets 3001 à 4000)  → ACK attendu 4001
  segment 3 : Seq 4001  (octets 4001 à 4500)  → ACK attendu 4501</div>
  <ul>
    <li><b>ACK cumulatif</b> : « ACK = n » confirme tous les octets jusqu'à n − 1. Le serveur peut donc n'envoyer qu'un seul ACK (4501) après les trois segments.</li>
    <li>SYN et FIN consomment chacun un numéro de séquence. Un ACK pur (sans données) n'en consomme pas.</li>
    <li><b>rwnd</b> (fenêtre de réception) : annoncée par le récepteur, c'est la place libre dans son tampon (contrôle de <b>flux</b>). <b>cwnd</b> (fenêtre de congestion) : fixée par l'émetteur pour ne pas saturer le réseau (contrôle de <b>congestion</b>).</li>
    <li><b>Fenêtre effective</b> W = min(cwnd, rwnd) : nombre maximal d'octets envoyés sans accusé de réception. Il reste à envoyer W − (octets déjà envoyés et non acquittés).</li>
  </ul>
  <div class="def"><b>Exemple (TD 2, ex. 4)</b>cwnd = 3000, rwnd = 2500, MSS = 1000 : W = min(3000, 2500) = 2500 octets, soit 1000 + 1000 + 500 (trois segments, dont le dernier est partiel). Si rwnd tombe à 1200, W = 1200 : après 1000 octets en vol, il ne reste que 200 octets à envoyer avant d'attendre un ACK. Dans la pratique, TCP peut attendre d'avoir de quoi remplir un segment complet, mais le TD compte le segment partiel.</div>
  <div class="def"><b>Perte de segments (TD 2, ex. 5)</b>Si les octets à partir du n° 501 sont perdus, le récepteur renvoie ACK = 501 (il redemande l'octet 501) et l'émetteur retransmet à partir de Seq = 501, après un délai d'attente ou plusieurs ACK identiques. Tout cela se joue à la couche <b>transport</b>. Si le récepteur réduit sa fenêtre à 500, ses ACK annoncent « fenêtre = 500 » et l'émetteur n'a plus le droit d'avoir plus de 500 octets en vol.</div>

{n27@72} MTU vs MSS ? :: MTU : taille maximale d'un paquet sur l'interface (Ethernet : 1500 octets).<br>MSS : taille maximale des données d'un segment TCP = MTU − 40 (20 IP + 20 TCP) → 1460.
{n28@73} Rôle d'une carte réseau ? :: Interface physique qui connecte un hôte au support du réseau. Elle porte l'adresse MAC.
{n28@74} Rôle d'un répéteur ? :: Régénérer (amplifier) le signal pour augmenter la distance. Couche 1 (physique).

{n42@139} ACK cumulatif ? :: « ACK = n » confirme tous les octets jusqu'à n − 1 : un seul accusé peut acquitter plusieurs segments reçus en ordre.

{n42@142} Perte à partir de l'octet 501 : que font récepteur et émetteur ? :: Le récepteur renvoie ACK = 501 (il redemande l'octet 501). L'émetteur retransmet à partir de Seq = 501. Cela se passe à la couche transport.
{n42@143} Un ACK pur (sans données) consomme-t-il des numéros de séquence ? :: Non : le Seq de celui qui l'envoie ne change pas. Seuls les octets de données, le SYN et le FIN en consomment.
